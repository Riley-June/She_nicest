# 轨迹 UI 设计与交互规格 V1

## 0. 给 AI UI 设计工具的生成指令

请设计一个移动端优先的私人自我陪伴 App，产品名为“轨迹”。

它帮助用户：

1. 说出此刻困住自己的问题；
2. 用 AI 把问题复述清楚；
3. 选择一个可承担的回应：小行动、荒诞尝试、先问清楚、暂时放下或只留下这一刻；
4. 保存文字、声音和图片组成的个人片段；
5. 在未来重新听见过去的自己。

请将产品理解为“自画像的回声”，而不是 Todo List、打卡 App、心理诊断工具或公开社区。

视觉气质：

- 安静、私密、有呼吸感；
- 低饱和度色块作为背景；
- 玻璃态表面承载对话、输入和操作；
- 有一点荒诞和人情味，但不轻浮；
- 有时间感，但不把过去美化成怀旧滤镜；
- 鼓励回应，但不产生 KPI 感。

设计优先级：

1. 让用户容易开始；
2. 让内容容易理解；
3. 让操作容易撤回；
4. 让原始记录优先于 AI 总结；
5. 让隐私设置不打断记录；
6. 在所有背景和玻璃态表面上保持可读性与可访问性。

不要生成：

- 社区、匿名发帖、评论、私信、关注、公开主页；
- 点赞、粉丝、热榜、排名；
- 连续打卡、积分、成就、完成率；
- 待办清单、截止日期、项目看板；
- 心理诊断、人格标签或治疗承诺；
- 强制任务、逾期、失败、中断等压力性状态。

## 1. 产品上下文

### 1.1 核心隐喻

“自画像”是用户在某一时刻留下的真实痕迹：

- 一句话；
- 一段声音；
- 一张图片；
- 后续可选的短视频；
- 一次行动；
- 一次改变方向；
- 一次有意识的暂停。

“回声”有两个时间尺度：

- **近处回声**：用户迈出一步或认真暂停后，这次回应对当下自己形成自我证据。
- **远处回声**：多年以后，过去的文字、声音、图片和回应重新进入现在，帮助未来的自己理解当时的自己。

产品原则：

> 每一次回应，都是一笔自画像；每一次回望，都是一声回声。

### 1.2 产品内部原则

> 帮助此刻的你回应，让未来的你理解。

### 1.3 体验闭环

~~~text
说出或留下此刻的自己
        ↓
AI 帮助把问题说清楚
        ↓
选择一种能够承担的回应
        ↓
行动、换方向、暂停或只保存
        ↓
留下一个自画像片段
        ↓
获得近处回声
        ↓
片段逐渐形成长期主题
        ↓
未来获得远处回声
~~~

## 2. 不可违背的产品约束

### 2.1 导航

- 底部只保留两个一级入口：“此刻”、“故事”。
- “设置”是全局弹窗入口，不作为底部 Tab。
- 设置按钮默认位于页面左上角。
- 在详情页左上角优先显示返回按钮，设置放入右上角更多菜单。
- 月度回望和年度回望属于“故事”内部，不单独占用一级导航。

### 2.2 输入

- 文字和声音是同等级的主要入口。
- 图片是可选附件。
- 视频是低频输入，V1 可作为后置能力或演示占位。
- 不要求用户先写标题、目标、分类、优先级或截止日期。
- 用户可以输入半句话、关键词或不完整描述。
- 标签是可选检索元数据，不是必填表单。
- 语音转写必须可编辑。
- 声音、图片和视频不默认自动播放。

### 2.3 回应

- 至少提供两个有实质差异的回应方向。
- V1 支持五类回应：小行动、荒诞尝试、先问清楚、暂时放下、只留下这一刻。
- 行动、换方向、暂停和只记录都不能显示为失败。
- 不显示完成率、积分、排名、连续天数或中断天数。
- 所有 AI 建议均可修改、拒绝、重试或跳过。

### 2.4 隐私

- 所有记录默认仅用户本人可见。
- 日常保存不显示一组隐私复选框。
- 新记录继承全局设置。
- 故事 / 主题可以覆盖全局设置。
- 单条记录只在需要时提供例外设置。
- 云端同步与 AI 使用分开授权。
- 设备权限只在使用麦克风、相册或摄像头时请求。
- 用户可以导出和删除原始内容及 AI 派生内容。

## 4. 视觉方向

### 4.1 视觉关键词

- low_saturation
- quiet
- private
- breathable
- soft_layer
- translucent_surface
- temporal
- slightly_absurd
- non_productivity
- readable

### 4.2 颜色角色

颜色使用语义角色，不用颜色单独表达成功、失败或重要程度。

| 角色 | 用途 | 视觉要求 |
|---|---|---|
| base_background | 页面总体背景 | 低饱和、低对比 |
| block_background | 背景色块或情绪底色 | 大面积、缓慢、不过度装饰 |
| glass_surface | 对话框、输入框、卡片 | 半透明、可读 |
| solid_surface | 长文本、历史列表、设置 | 更不透明、更稳定 |
| primary_action | 当前主要回应 | 清晰、比普通玻璃更不透明 |
| secondary_action | 次要操作 | 轻量、边界清楚 |
| text_primary | 主文本 | 高对比 |
| text_secondary | 辅助说明 | 仍需足够可读 |
| separator | 分隔层级 | 低对比但可辨识 |

建议色彩方向：

- 雾蓝
- 灰绿
- 暖沙
- 淡紫
- 雾粉
- 纸白

不要使用高饱和荧光色作为主要背景，也不要用红绿颜色单独表达状态。

### 4.3 玻璃态规则

玻璃态只用于功能层，不覆盖所有内容。

适合：

- 对话输入区；
- AI 复述卡；
- 回应选择卡；
- 设置底部抽屉；
- 日期 / 标签筛选面板；
- 近处回声卡；
- 媒体预览层。

不适合：

- 大段年度回望正文；
- 高密度历史列表；
- 复杂设置表单；
- 删除和隐私确认页面；
- 需要长时间阅读的内容。

玻璃态必须具备：

- 清晰边界；
- 足够文字对比度；
- 轻微背景模糊；
- 轻量阴影，不做夸张悬浮；
- 在“减少透明度”时自动退化为不透明卡片；
- 背景复杂时自动增加表面不透明度；
- 不用透明度单独表示是否可点击。

### 4.4 推荐视觉参数

以下参数用于原型起点，不是固定实现值：

| 属性 | 起点 |
|---|---|
| 页面圆角 | 20–28 |
| 小组件圆角 | 12–16 |
| 玻璃表面透明度 | 60%–85%，根据对比度自动调整 |
| 背景模糊 | 16–24px，移动端性能不足时降低 |
| 边框 | 1px 低对比描边 |
| 阴影 | 柔和、低扩散、低不透明度 |
| 页面内边距 | 20–24 |
| 控件最小触控区域 | 44×44pt |
| 动效 | 短、慢、可关闭，优先淡入和位移 |

### 4.5 背景更换

设置路径：

~~~text
设置
└── 操作与外观
    └── 界面背景
~~~

V1 提供：

- 4–6 个低饱和背景预设；
- 1–2 个低对比度渐变；
- 1 个纸张 / 细颗粒选项；
- 可选的用户图片背景实验入口。

如果允许用户选择图片：

- 自动裁切；
- 自动降低饱和度；
- 自动加遮罩和模糊；
- 自动检查文字可读性；
- 尽量去除非必要元数据；
- 提供“恢复默认背景”。

背景只承担情绪，不承担功能状态。

### 4.6 左手 / 右手布局

设置路径：

~~~text
设置
└── 操作与外观
    └── 操作习惯
        ├── 左手
        ├── 右手
        └── 不调整
~~~

布局规则：

- 默认使用“不调整 / 居中”；
- 只调整高频操作，不镜像整个界面；
- 可调整：语音、发送、添加媒体、主要回应、保存；
- 保持稳定：返回、设置、底部导航、阅读顺序；
- 设置页提供小型布局预览；
- 切换后立即生效；
- 所有按钮仍满足最小触控区域。

## 5. 全局外壳

### 5.1 底部导航

~~~text
┌─────────────────────────┐
│                         │
│       页面内容           │
│                         │
├─────────────────────────┤
│        此刻       故事    │
└─────────────────────────┘
~~~

要求：

- 只有两个 Tab；
- 图标 + 文字同时存在；
- 当前 Tab 有明确状态，不仅靠颜色；
- 导航不因左右手模式整体镜像；
- 适配安全区域；
- 不在底部导航放账号头像或个人主页。

### 5.2 顶部栏

此刻：

~~~text
┌─────────────────────────┐
│ 设置                 回望 │
└─────────────────────────┘
~~~

故事：

~~~text
┌─────────────────────────┐
│ 设置                 故事 │
└─────────────────────────┘
~~~

详情页：

~~~text
┌─────────────────────────┐
│ 返回          页面标题   更多 │
└─────────────────────────┘
~~~

### 5.3 设置入口

- 设置图标位于主页面左上角；
- 点击后出现底部抽屉；
- 底部抽屉显示设置分组；
- 点击分组后可扩展为全屏设置页；
- 所有模态页面都有明确关闭 / 返回路径；
- 不叠加多个模态窗口；
- 未保存的设置关闭前需要给出保留或放弃选择。

## 6. 页面规格

## 6.1 M01 · 此刻空状态

### 目标

让用户不用整理好自己，就愿意开始。

### 页面内容

~~~text
设置                         回望

现在，有什么事在你脑子里打转？

不用想清楚，先留下一点。

┌─────────────────────────┐
│ 写下你现在卡住的一句话……    │
│                         │
│ [说一段] [添加图片]        │
└─────────────────────────┘

                    此刻     故事
~~~

### 组件

- top_bar
- prompt_text
- text_composer
- voice_button
- media_button
- bottom_navigation

### 交互

- 点击输入框进入 M02；
- 点击说一段进入 M03；
- 点击添加图片请求相册 / 相机权限；
- 不要求先选择标签；
- 不展示任务列表和数据指标。

---

## 6.2 M02 · 文字输入

### 目标

支持半句、关键词和不完整描述。

### 页面内容

~~~text
写下你现在卡住的一句话

半句话也可以。

┌─────────────────────────┐
│ 我想换工作，但不知道是不是在逃避 │
│                         │
└─────────────────────────┘

[添加图片] [添加标签]

[继续]             [取消]
~~~

### 交互规则

- 多行输入；
- 支持粘贴、撤销和编辑；
- 本地自动保存草稿；
- 空内容不能提交，但不使用责备性错误；
- 继续后进入 M04；
- 取消时提供“保留草稿 / 删除草稿”。

---

## 6.3 M03 · 声音输入

### 目标

让用户用自然语言留下当时的语气、停顿和犹豫。

### 页面状态

#### 未录音

~~~text
说到哪儿算哪儿。

[开始录音]
~~~

#### 正在录音

~~~text
正在听你说

00:12

[停止] [取消]
~~~

#### 转写完成

~~~text
这是刚才的你：

“我想换工作，但不知道是不是在逃避。”

[编辑文字稿] [重新录音]

[继续]
~~~

### 交互规则

- 点击时才请求麦克风权限；
- 不使用必须长按的录音手势；
- 录音状态清晰可见；
- 文字稿必须可编辑；
- 默认不长期保存原始声音，除非用户设置允许；
- 录音失败时提供文字输入替代；
- 关闭麦克风权限不影响文字功能。

---

## 6.4 M04 · AI 复述

### 目标

先帮助用户确认自己被听见，再提供回应方向。

### 页面内容

~~~text
我听见你现在卡住的是：

“你想离开现在的工作，
但不确定自己是真的想走，
还是只是最近太累了。”

这句话像你吗？

[改一下] [换一种说法] [就是这个] [跳过]
~~~

### 组件

- ai_label
- reflection_card
- edit_action
- retry_action
- confirm_action
- skip_action

### 交互规则

- 明确标注 AI 辅助；
- 默认不超过三句话；
- 不使用心理诊断和人格标签；
- 用户可以逐字编辑；
- 用户确认前不进入长期主题；
- AI 失败时提供手动路径；
- 原始输入始终保留。

---

## 6.5 M05 · 回应选择

### 目标

让用户选择一个方向，而不是接受一个任务。

### 页面内容

~~~text
这一次，你想怎么回应它？

┌─────────────────────────┐
│ 迈一小步                  │
│ 一个现在就能开始的动作      │
└─────────────────────────┘

┌─────────────────────────┐
│ 来个歪招                  │
│ 不一定有用，但可以先试试    │
└─────────────────────────┘

┌─────────────────────────┐
│ 先问清楚                  │
│ 先理解自己真正害怕什么      │
└─────────────────────────┘

┌─────────────────────────┐
│ 今天先放下                │
│ 这件事今天不解决也可以      │
└─────────────────────────┘

┌─────────────────────────┐
│ 只留下这一刻              │
│ 我现在只想承认它存在        │
└─────────────────────────┘

[换一组回应]
~~~

### 交互规则

- 五类回应同等可见；
- 至少展示两个实质不同的方向；
- 用户可以编辑 AI 建议；
- 暂停不显示为失败；
- 荒诞建议必须低风险、可撤回；
- 高风险内容不生成荒诞建议；
- 用户可以不选择并退出。

## 6.6 M06 · 回应执行

### 页面内容

~~~text
你现在试的是：

只打开招聘网站，看三个职位。

不用完成得漂亮。
回来告诉自己发生了什么就好。

[我试过了]
[我换了个方法]
[我先停在这里]
~~~

### 约束

不出现：

- 倒计时；
- 逾期；
- 进度条；
- 完成百分比；
- 连续打卡；
- 失败计数；
- 默认催促通知。

---

## 6.7 M07 · 结果记录与近处回声

### 页面内容

~~~text
刚才发生了什么？

[有一点进展]
[没发生什么]
[我换了个方法]
[发现了别的问题]
[我发现今天不适合做]
[我还没开始]

想写一句也可以。

┌─────────────────────────┐
│                         │
│                         │
└─────────────────────────┘

[添加声音] [添加图片]

[留下这个片段]
~~~

保存反馈：

~~~text
这个片段已经留下了。

你刚刚没有解决全部问题，
但你对它作出了一次回应。
~~~

### 交互规则

- 用户可以只选结果；
- 用户可以补充文字、声音或图片；
- “没发生什么”和“还没开始”不是错误；
- 保存后不显示得分、等级和完成率；
- 近处回声必须基于用户真实选择，不使用空泛夸奖；
- 用户可以关闭 AI 生成反馈。

---

## 6.8 M08 · 暂时放下

### 页面内容

~~~text
好，今天先放下。

你不需要为没有行动解释。

[现在没有力气]
[还没准备好]
[这件事暂时不重要]
[我只是想先承认它存在]
[不留下原因]

[留下这个选择]
~~~

### 交互规则

- 原因是可选的；
- 暂时放下与行动记录拥有同等数据地位；
- 不显示未完成、中断、逾期或失败；
- 用户可以以后重新打开；
- 用户可以删除该记录；
- 默认不自动发送“你还没回来”的提醒。

## 6.9 S01 · 故事总览

### 目标

让短期片段和长期主题在同一个入口中自然出现。

### 页面内容

~~~text
故事

[历史] [主题] [回望]

最近的事
可以在一段时间内告一段落的问题

换工作
4 个片段 · 最近一次：昨天

开始运动
~~~

## 6.13 S03 · 长期主题提示

### 页面内容

- 用户确认后才建立主题；
- 用户拒绝后短期内不重复打扰；
- 主题名称优先使用用户原话；
- 不使用“你一直没有解决这个问题”。

## 6.16 S06 · 回望

### 二级切换

~~~text
回望

[月度回望] [年度回望]
~~~

### 月度回望

内容模块：

- 这个月反复出现的事；
- 这个月真正试过的事；
- 这个月选择放下的事；
- 这个月某个时刻的自己；
- 写给下个月的自己。

### 年度回望

内容模块：

- 这一年反复出现的事；
- 这一年真正试过的事；
- 这一年选择放下的事；
- 发生变化的长期主题；
- 某个时刻的自己；
- 写给未来的自己。

AI 草稿示例：

~~~text
今年的我没有变得特别勇敢。

但我比去年多试了一次，
也多理解自己几次。

如果以后又忘了当时为什么出发，
希望你能回来看看。
~~~

### 规则

- AI 生成部分必须明确标注；
- 每个总结可以查看来源片段；
- AI 不得捏造原始记录中没有的事件和情绪；
- 用户可以修改、保存、导出或删除；
- 不显示完成率、排名、评分、连续天数和成长等级；
- 记录较少时使用：
  “这一段时间还没有形成完整回望，但已经留下了几次回应。”

## 7. 组件规格

### 7.1 glass_card

用途：对话卡、回应卡、近处回声卡。

要求：

- 背景半透明；
- 1px 边界；
- 圆角 16–24；
- 内边距 16–20；
- 支持不透明度自动提升；
- 长文本超过一定长度时切换为 solid_surface。

### 7.2 text_composer

包含：

- 多行输入框；
- 语音入口；
- 图片入口；
- 视频入口（后置 / 占位）；
- 标签入口；
- 发送或继续按钮。

规则：

- 文字默认可输入；
- 语音和文字同等级；
- 图片和视频是附件；
- 标签可选；
- 主按钮位置适配左右手；
- 不显示字数限制，除非技术上必要。

### 7.3 response_card

字段：

- response_type
- title
- description
- risk_level
- editable
- source

五种类型：

- small_action
- absurd_try
- clarify
- pause
- capture_only

### 7.4 media_chip

显示：

- 媒体类型；
- 时长或数量；
- 是否有文字稿；
- 是否仅保存在本机。

声音和视频不自动播放。

### 7.5 tag_chip

要求：

- 显示文字；
- 可删除；
- 可编辑；
- 不依赖颜色识别；
- 不与长期主题混淆。

### 7.6 echo_card

字段：

- echo_type：near / far
- source_text
- source_media
- generated_text
- source_references
- dismissible
- recall_permission

要求：

- AI 生成内容必须有标识；
- 近处回声基于用户刚刚的事实；
- 远处回声优先展示原话；
- 用户可以关闭、删除和不再主动召回。

### 7.7 filter_control

历史页顶部使用两个并列控件：

- 日期；
- 标签。

控件保持紧凑，复杂选择通过底部面板完成。

### 7.8 settings_sheet

要求：

- 从底部出现；
- 有标题和关闭按钮；
- 先显示分组；
- 不在一层展示过多开关；
- 复杂设置进入同一模态空间的详情页；
- 支持返回；
- 不同时叠加第二个模态窗口。

## 8. 交互状态与状态机

### 8.1 记录状态

~~~text
idle
  ↓
drafting
  ↓
captured
  ↓
reflecting
  ↓
choosing_response
  ↓
trying / changed_method / paused / capture_only
  ↓
recorded
~~~

允许从任意可编辑状态：

- 返回上一步；
- 修改原文；
- 删除草稿；
- 跳过 AI；
- 取消保存。

### 8.2 AI 状态

~~~text
not_requested
  ↓
processing
  ↓
ready
  ├── accepted
  ├── edited
  ├── retried
  ├── rejected
  └── skipped
~~~

AI 失败：

~~~text
processing
  ↓
unavailable
  ├── retry
  ├── manual_edit
  └── continue_without_ai
~~~

### 8.3 同步状态

~~~text
local_only
  ↓
sync_requested
  ↓
syncing
  ├── synced
  └── sync_failed
~~~

同步失败不改变用户已保存的本地内容。

### 8.4 删除状态

~~~text
delete_requested
  ↓
confirm_scope
  ↓
deleting_original
  ↓
deleting_derivatives
  ↓
deleting_cloud_copy
  ↓
deleted
~~~

## 9. AI 交互规范

### 9.1 AI 角色

AI 是：

- 困扰复述器；
- 回应拆解器；
- 荒诞尝试提供者；
- 片段整理助手；
- 长期主题发现助手；
- 月度 / 年度回望写作助手。

AI 不是：

- 任务管理者；
- 自律教练；
- 心理诊断者；
- 人生裁判；
- 用户记忆的最终解释者。

### 9.2 AI 输出语气

优先：

- 可以试试；
- 也许；
- 如果你愿意；
- 我可能理解错了；
- 这只是一个方向；
- 你也可以换一个。

避免：

- 你必须；
- 你应该；
- 不要再拖延；
- 任务失败；
- 你还没有解决；
- 根据你的心理状态；
- 你一定是因为……

### 9.3 AI 透明度

- 每个 AI 输出都标记“AI 辅助”；
- 原始用户输入始终可查看；
- AI 摘要提供来源片段；
- 用户可以修改、拒绝、重试、跳过和删除；
- AI 不可用时核心记录仍可完成；
- AI 不把推测写成事实。

## 10. 内容与文案规范

### 10.1 推荐文案

- 先说半句；
- 留下一点也可以；
- 我听见你现在卡住的是；
- 这句话像你吗；
- 你可以试试这个；
- 也可以换一个方向；
- 这件事今天不解决也可以；
- 我现在只想承认它存在；
- 这个片段已经留下了；
- 要听听当时的你吗；
- 以后想回来时，它还在；
- 这一次的你不必和上一次一样。

### 10.2 禁止文案

- 你必须；
- 你应该；
- 不要拖延；
- 坚持下去；
- 任务失败；
- 已中断；
- 逾期；
- 完成率；
- 连续打卡；
- 成长值；
- 你还没有解决这个问题；
- 大家都认为你应该。

### 10.3 空状态

空状态不使用：

- 暂无数据；
- 还没有完成任何任务；
- 你还没有开始；
- 记录不足。

改用：

- 这里还没有形成回声；
- 你可以先留下半句；
- 这一段时间还没有形成完整回望，但已经留下了几次回应。

## 11. 多媒体和隐私

### 11.1 媒体优先级

V1：

1. 文字；
2. 声音；
3. 图片；
4. 视频后置。

### 11.2 内容层级

~~~text
原始内容
├── 用户文字
├── 原始声音
├── 图片
└── 后续短视频

文字层
├── 声音转写
├── 图片说明
└── 视频字幕

叙事层
├── 回应
├── 片段
├── 故事
├── 长期主题
└── 批注

AI 派生层
├── AI 复述
├── 摘要
├── 主题建议
├── 搜索索引
└── 月度 / 年度草稿
~~~

原始内容不能被 AI 派生内容覆盖。

### 11.3 隐私继承

~~~text
全局默认设置
        ↓
故事 / 长期主题覆盖
        ↓
单条记录例外
~~~

普通记录不显示一排隐私标签。只有和默认设置不同的记录才显示：

- 仅本机；
- 不参与 AI；
- 不主动召回；
- 不参与回望。

## 12. 可访问性和响应式要求

- 核心控件触控区域至少 44×44pt；
- 支持系统字体放大；
- 不依靠颜色单独表达状态；
- 声音必须有文字稿；
- 图片允许用户添加文字说明；
- 后续视频需要字幕或文字摘要；
- 支持深色模式；
- 支持增强对比度；
- 支持减少透明度；
- 支持减少动态效果；
- 不自动播放声音和视频；
- 重要提示不依赖自动消失；
- 支持屏幕阅读器标签；
- 语音功能不能成为唯一输入方式；
- 横屏和小尺寸屏幕不发生内容重叠；
- 背景更换不能破坏正文对比度；
- 玻璃态失败时回退为不透明表面。

- 不请求不必要权限；
- 默认使用临时会话；
- 体验结束后自动删除临时数据；
- 不允许公开展示参观者真实内容；
- 远处时间线必须标注为“产品机制演示”；
- 网络或 AI 失败时使用预制回复；
- 不把 demo 数据写入正式用户历史。

---

## 14. 验收标准

### 14.1 导航

- 底部只有“此刻”和“故事”；
- 设置从左上角打开弹窗；
- 月度 / 年度回望属于故事；
- 详情页返回路径清楚。

### 14.2 记录

- 用户可以不填写标题直接记录；
- 用户可以使用文字或声音；
- 用户可以添加图片；
- 语音转写可编辑；
- 用户可以跳过 AI；
- 用户可以选择五类回应；
- 用户可以只保存当下；
- 暂停不显示失败；
- 不出现 KPI 组件。

### 14.3 故事与回声

- 历史页顶部有日期和标签筛选；
- 标签是可选元数据；
- 长期主题必须经过用户确认；
- 主题时间线展示不同阶段回应；
- 远处回声按“一句话 → 感官入口 → 完整上下文”展开；
- 声音和视频不自动播放；
- 用户可以关闭主动召回。

### 14.4 设置与外观

- 用户可以选择左手、右手或不调整；
- 高频按钮随设置调整位置；
- 返回、导航和阅读顺序保持稳定；
- 用户可以更换低饱和背景；
- 背景切换不破坏可读性；
- 玻璃态在减少透明度时回退为不透明表面；
- 设置不打断当前记录。

### 14.5 隐私

- 默认仅用户本人可见；
- 日常保存不重复设置隐私状态；
- 云同步与 AI 授权分开；
- 麦克风、相册和摄像头按需请求；
- 用户可以导出和删除原始内容及派生数据；
- 删除范围明确；
- AI 不可用时仍可记录和回望。

## 15. 设计输出要求

AI UI 设计工具最终应输出：

1. 移动端高保真页面；
2. 低饱和背景变体；
3. 玻璃态与不透明回退变体；
4. 左手 / 右手布局变体；
5. 文字输入、声音输入、图片附件状态；
6. AI 复述、回应选择、近处回声；
7. 故事历史、日期筛选、标签筛选；
8. 长期主题时间线；
9. 月度 / 年度回望；
10. 设置底部抽屉和详情页；
11. 加载、失败、空状态、删除确认状态；
12. 深色、增强对比度、减少透明度状态。

最终判断标准：

> 它是否让用户更容易回应和理解自己，而不是把产品重新做成一个管理用户的系统？
